# ۰۰ | انتخاب Stack فنی

**پروژه:** پلتفرم فروش و معرفی محصولات مبلمان اداری (فروشگاهی + Portfolio + CRM + باشگاه مشتریان)
**نوع کار:** Vibe Coding با هوش مصنوعی — Stack باید یک‌ریپو (monorepo نه، بلکه single-repo)، تایپ‌سیف و کم‌اصطکاک باشد تا AI بتواند مرحله‌به‌مرحله و بدون گم‌کردن context پیش برود.

---

## ۱. تصمیم نهایی

| لایه | تکنولوژی | دلیل اصلی انتخاب |
|---|---|---|
| Framework اصلی | **Next.js 15 (App Router) + TypeScript** | SSR/SSG برای سئو، routing استاندارد و تمیز، پشتیبانی رسمی i18n، اکوسیستم بزرگ برای AI code-gen |
| CMS + Auth + API | **Payload CMS 3 (Embedded در Next.js)** | همان ریپو و همان سرور Next.js اجرا می‌شود؛ پنل مدیریت به‌صورت خودکار از روی اسکیمای TypeScript ساخته می‌شود؛ Auth، Access Control و Admin UI رایگان و آماده است — نیازی به ساخت پنل ادمین جدا نیست |
| دیتابیس | **PostgreSQL** (روی Liara Managed Database) | داده‌های رابطه‌ای؛ Liara امکان Connection Pooling دارد |
| ذخیره‌سازی مدیا | **Liara Object Storage** (سازگار با S3 API) — جایگزین ArvanCloud Object Storage | Cloudflare R2 کنار گذاشته شد (توضیح در پایین) |
| هاست | **Liara** (PaaS ایرانی، دیپلوی مستقیم Next.js با تجربه‌ای شبیه Vercel) — جایگزین ArvanCloud Cloud Server | Vercel کنار گذاشته شد (توضیح در پایین) |
| ایمیل تراکنشی | **Liara Email Server** (یا SMTP اختصاصی) | Resend کنار گذاشته شد (توضیح در پایین) |
| مانیتورینگ خطا | **GlitchTip، Self-hosted** روی همان سرور (متن‌باز، سازگار با SDK/DSN همان `@sentry/nextjs`) | Sentry.io کنار گذاشته شد (توضیح در پایین)؛ فقط آدرس DSN عوض می‌شود، کد یکسان می‌ماند |
| استایل | **Tailwind CSS v4 + shadcn/ui** | سرعت بالا در تولید UI با AI، اکسسیبیلیتی داخلی کامپوننت‌ها، سفارشی‌سازی کامل توکن‌های طراحی |
| موشن و اسکرول | **GSAP (ScrollTrigger) + Lenis (Smooth Scroll)** | استاندارد صنعتی برای روایت‌های اسکرول‌بیس (scrollytelling) و انیمیشن‌های پیچیده و کنترل‌شده |
| سه‌بعدی | **React Three Fiber + drei** | لایه React روی Three.js؛ برای نمایش سه‌بعدی محصولات مبلمان و صحنه‌ی Hero |
| میکرو-اینترکشن UI | **Framer Motion** | ترنزیشن کامپوننت‌ها، مودال‌ها، منوها — جدا از لایه‌ی روایت اسکرول (GSAP) |
| چندزبانگی | **next-intl** | Routing استاندارد مبتنی بر پیشوند locale (`/fa`, `/en`)، مدیریت رشته‌های ترجمه، سازگار با App Router |
| مدیریت State/Data | **TanStack Query + Zustand** | کش و همگام‌سازی داده‌ی سرور (سبد خرید، محصولات) + state سبک UI (منو، مودال، تم) |
| جستجو | **Meilisearch** (self-hosted) | جستجوی تایپ‌ای-هد چندزبانه، سریع، بدون هزینه‌ی بالای Algolia |
| پرداخت | **درگاه پرداخت بانکی ایرانی** (زرین‌پال/آیدی‌پی/زیبال/نکست‌پی — انتخاب نهایی طبق قرارداد PSP) | فروش فعلاً فقط داخل ایران است؛ Stripe به‌دلیل محدودیت‌های بین‌المللی برای کسب‌وکار ایرانی قابل‌استفاده نیست |

> **به‌روزرسانی فاز ۰ (تعیین‌شده):** فروش آنلاین فعلاً فقط داخل ایران است (بدون صادرات فعلی)؛ Checkout و حمل‌ونقل فقط برای آدرس داخل ایران فعال می‌شود.

## ۱.۱ چرا Vercel/Neon-Supabase/R2/Resend/Sentry کنار گذاشته شدند (تصمیم تحقیق‌شده)

این چهار سرویس همگی شرکت‌های آمریکایی هستند و تحت الزامات تحریمی OFAC (همان چارچوبی که برای ایران، کوبا، کره‌شمالی و... اعمال می‌شود) قانوناً موظف‌اند دسترسی کسب‌وکارهای ایرانی را محدود یا مسدود کنند. این یک محدودیت فیلترینگ از سمت ایران نیست که با VPN حل شود — خود شرکت‌ها حساب را می‌بندند، چون این بخشی از قوانین شرکت (ToS) آن‌هاست:

- **Cloudflare:** طبق اعلام رسمی خودشان (گزارش به SEC، ۲۰۱۹)، از سال ۲۰۱۸ به‌عنوان سیاست شرکت، به مشتریان جدید در ایران فقط سرویس‌های **رایگان** می‌دهند — یعنی R2 (که پولی است) برای یک شرکت ایرانی اصلاً در دسترس نیست.
- **Vercel:** در تاپیک‌های پشتیبانی خودشان تأیید کرده‌اند که برای کشورهای تحت تحریم OFAC «تضمینی برای Deliverability» نمی‌دهند و ارائه‌دهنده‌ی زیرساختشان (AWS) این کشورها را مسدود می‌کند؛ حتی یک Template آماده برای مسدودکردن کشورهای OFAC در Firewall خودشان دارند.
- **Sentry:** سابقه‌ی مستند دارد که برای کشورهای تحریمی (مثلاً روسیه از ۲۰۲۴) دسترسی را کاملاً قطع و از پذیرش پرداخت خودداری می‌کند؛ همان چارچوب قانونی برای ایران هم صدق می‌کند.
- **Resend:** شرکت آمریکایی دیگری با همین الگوی رایج در ToS اکثر SaaSهای آمریکایی (محدودیت برای کشورهای تحت تحریم جامع) — قبل از اعتماد کامل، حتماً بخش Terms of Service آن‌ها را مستقیماً چک کن.

**نتیجه:** حتی با VPN، ساختن یک کسب‌وکار واقعی روی این سرویس‌ها ریسک بالایی دارد — هر لحظه ممکن است حساب (و داده‌های داخلش: عکس محصولات، ایمیل مشتریان، تاریخچه‌ی سفارش) بدون اخطار قطع شود. **جایگزین‌های ایرانی که در جدول بالا انتخاب شدند:**

- **Liara (لیارا)** — انتخاب اصلی؛ یک PaaS ایرانی که دیپلوی مستقیم Next.js، دیتابیس مدیریت‌شده‌ی Postgres، Object Storage سازگار با S3، و یک سرویس Email Server یکپارچه دارد — عملاً جایگزین همه‌ی ۴ سرویس با یک ارائه‌دهنده.
- **ArvanCloud (آروان‌کلود)** — جایگزین/مکمل برای CDN، Cloud Server، و Object Storage، اگر خواستی بین دو ارائه‌دهنده مقایسه کنی یا بار را پخش کنی.
- **GlitchTip (Self-hosted)** — نسخه‌ی متن‌باز و سبک‌تر از Sentry؛ همان SDK رسمی `@sentry/nextjs` را بدون تغییر کد نگه می‌داری، فقط DSN را به سرور خودت (روی Liara/ArvanCloud) اشاره می‌دهی.

> ⚠️ نام برند شما «اروند» (Arvand) و نام این ارائه‌دهنده «آروان‌کلود» (ArvanCloud) شبیه هم هستند ولی **دو نهاد کاملاً بی‌ربط**اند — در مستندات داخلی این تفاوت را برای تیم روشن نگه دار.
>
> پیش از تعهد نهایی (فاز ۱)، قیمت/محدودیت‌های فعلی Liara و ArvanCloud را مستقیم از سایت‌شان چک کن — این تحقیق تاریخ تحریم/دسترسی را تأیید کرد، نه لزوماً آخرین تعرفه یا محدودیت فنی دقیق آن‌ها را.

## ۱.۲ توسعه‌ی کاملاً لوکال قبل از نهایی‌شدن پروژه (Local-First)

**تصمیم:** تا فاز ۱۱ (Deployment)، **هیچ سرویس ابری‌ای وصل نمی‌شود** — همه‌چیز روی لپ‌تاپ اجرا می‌شود. فقط در فاز ۱۱، معادل‌های نهایی (Liara/درگاه واقعی) برای اولین بار وصل می‌شوند.

| لایه | نسخه‌ی توسعه (فاز ۱ تا ۱۰، روی لپ‌تاپ) | نسخه‌ی نهایی (فقط فاز ۱۱) |
|---|---|---|
| دیتابیس | PostgreSQL روی Docker Compose | Liara Managed Postgres |
| ذخیره‌سازی مدیا | **Payload Local Disk Storage** — پوشه‌ی `media/` همان پروژه، بدون هیچ S3 | Liara Object Storage |
| ایمیل تراکنشی | **Mailhog** (SMTP جعلی روی Docker؛ ایمیل «ارسال‌شده» را در `localhost:8025` می‌بینی، چیزی واقعاً ارسال نمی‌شود) | Liara Email Server |
| پرداخت | **Mock Payment Provider** — یک Route داخلی خودمان که دقیقاً همان قرارداد (Request/Response/Callback) درگاه واقعی را شبیه‌سازی می‌کند؛ یک صفحه‌ی ساختگی با دو دکمه‌ی «پرداخت موفق» / «پرداخت ناموفق» | درگاه بانکی ایرانی واقعی (زرین‌پال/آیدی‌پی/...) |
| مانیتورینگ خطا | هیچی — فقط Console/Log لوکال کافی است | GlitchTip Self-hosted |
| هاست | `npm run dev` (یا `next start` برای تست شبیه Production) روی همان لپ‌تاپ | Liara/ArvanCloud |
| فونت (Peyda + Manrope) | **Self-hosted از همان فاز ۱** — فایل‌های `.woff2` داخل `public/fonts/` + `next/font/local`، نه لینک به Google Fonts CDN | همان، بدون تغییر (Self-hosted می‌ماند حتی در Production) |
| جستجو (Meilisearch) | Docker — از قبل لوکال بود | همان Docker، فقط روی سرور |

### Docker Compose برای فاز ۱ (اسکلت)
```yaml
# docker-compose.yml — فقط برای توسعه‌ی لوکال
services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB: arvand
      POSTGRES_USER: arvand
      POSTGRES_PASSWORD: localdev
    ports: ["5432:5432"]
    volumes: ["pgdata:/var/lib/postgresql/data"]

  meilisearch:
    image: getmeili/meilisearch:v1.10
    environment:
      MEILI_MASTER_KEY: localdev-key
    ports: ["7700:7700"]
    volumes: ["meilidata:/meili_data"]

  mailhog:
    image: mailhog/mailhog
    ports:
      - "1025:1025"   # SMTP — همین را در .env بگذار
      - "8025:8025"   # وب UI برای دیدن ایمیل‌ها

volumes:
  pgdata:
  meilidata:
```
با `docker compose up -d` هر سه سرویس بالا می‌آیند؛ بعد از اولین Pull، کاملاً آفلاین کار می‌کند.

### Mock Payment Provider — طراحی
یک ماژول `lib/payment/providers/mock.ts` که همان اینترفیس `lib/payment/providers/zarinpal.ts` (و بقیه) را پیاده می‌کند (مثلاً `createPayment()`, `verifyPayment()`). یک صفحه‌ی داخلی `/[locale]/mock-bank` صفحه‌ی «درگاه» را شبیه‌سازی می‌کند. سوییچ بین Mock و واقعی فقط با یک متغیر محیطی (`PAYMENT_PROVIDER=mock` در `.env.local`، `PAYMENT_PROVIDER=zarinpal` در Production) انجام می‌شود — کد Checkout هیچ تغییری نمی‌کند.

### چرا فونت‌ها را Self-hosted می‌کنیم (نه فقط برای Local)
جدا از توسعه‌ی آفلاین، Google Fonts CDN گاهی از ایران کند/ناپایدار لود می‌شود — پس Self-hosted بودن هم برای توسعه‌ی لوکال خوب است، هم برای کاربر نهایی در Production بهتر و پایدارتر است. یعنی این یک تصمیم دائمی است، نه فقط یک Workaround موقت.

## ۲. چرا این ترکیب برای Vibe Coding مناسب است؟

1. **تک‌ریپو، تک‌سرور:** Payload به‌صورت Embedded داخل Next.js اجرا می‌شود، یعنی AI مجبور نیست هم‌زمان دو پروژه‌ی جدا (بک‌اند و فرانت) را مدیریت کند و context را از دست ندهد.
2. **اسکیمای TypeScript = مستند زنده:** تعریف هر Collection در Payload هم مدل داده است، هم مستند، هم پنل ادمین. برای AI که قدم‌به‌قدم پیش می‌رود، این یعنی کمترین حدس‌زدن.
3. **Type Safety سرتاسری:** از دیتابیس تا کامپوننت React، تایپ‌ها به‌صورت خودکار تولید می‌شوند → خطاهای رایج AI-generated code (اسم فیلد اشتباه، شکل داده‌ی نادرست) در Compile Time گرفته می‌شود.
4. **URL و SEO استاندارد به‌صورت پیش‌فرض:** App Router + next-intl یعنی ساختار URL تمیز و چندزبانه از روز اول درست تعریف می‌شود، نه اینکه بعداً Refactor شود.
5. **جداسازی لایه‌ی موشن:** GSAP برای روایت اسکرول، Framer Motion برای تعامل UI — تداخل و شلوغی کد جلوگیری می‌شود.

## ۲.۱ سیاست استفاده از کتابخانه‌های موشن/سه‌بعدی (مهم — محدودیت وابستگی)

**تصمیم:** هیچ‌کدام از سه کتابخانه‌ی GSAP+ScrollTrigger+Lenis، Framer Motion، و React Three Fiber+drei نباید به‌صورت Global و روی همه‌ی صفحات لود/استفاده شوند. هرکدام فقط **دقیقاً همان‌جایی که کارکرد را بهتر می‌کند** به‌کار می‌رود، به‌صورت Lazy-load و مجزا از هم.

**اولویت و میزان استفاده (از بیشترین به کمترین):**

| کتابخانه | نقش | میزان استفاده |
|---|---|---|
| **GSAP (ScrollTrigger) + Lenis** | ابزار اصلی و غالب پروژه برای روایت اسکرول (Scrollytelling)، پین‌شدن بخش‌ها، ترنزیشن بین سکشن‌ها | بیشترین — در بیشترین تعداد صفحه (Home، About، جزئیات محصول، Portfolio) |
| **Framer Motion** | فقط برای میکرو-اینترکشن‌های UI مبتنی بر رویداد کاربر (باز/بسته‌شدن منو و مودال، تأیید افزودن به سبد، Toast) | متوسط — محدود به کامپوننت‌های تعاملی مشخص، نه سکشن‌های صفحه |
| **React Three Fiber + drei** | فقط برای صحنه‌ی Hero برند و Viewer سه‌بعدی محصول (اگر مدل glTF موجود باشد) | کمترین — حداکثر ۲ الی ۳ نقطه‌ی مشخص در کل سایت، همیشه با Fallback سبک برای موبایل |

**قواعد اجرایی برای AI:**
- قبل از افزودن هرکدام از این سه کتابخانه به یک صفحه/کامپوننت جدید، اول بررسی کن آیا واقعاً لازم است یا با CSS Transition ساده/Tailwind قابل انجام است.
- Import این کتابخانه‌ها همیشه Dynamic و محدود به همان کامپوننت باشد؛ هرگز در `layout.tsx` سراسری import نشوند.
- اگر صفحه‌ای نیاز به هیچ‌کدام ندارد، هیچ‌کدام اضافه نشود — «مدرن بودن» به معنای استفاده‌ی همه‌جا نیست.

## ۳. گزینه‌های بررسی‌شده و رد شده
