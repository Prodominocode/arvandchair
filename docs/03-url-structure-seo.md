# ۰۳ | ساختار URL و اصول سئو

## ۱. اصول کلی URL
- تمام URLها **lowercase**، با خط تیره `-` بین کلمات (نه underscore)
- بدون Query String برای مسیرهای اصلی محتوا (فیلترها استثنا هستند — بخش ۳)
- Slug هر محصول/دسته/پست باید **در هر زبان جداگانه و معنادار** باشد (نه فقط ترجمه‌ی عنوان به‌صورت خودکار — باید توسط ویرایشگر تأیید شود)
- بدون Trailing Slash اضافه؛ یک الگوی ثابت در کل سایت (تصمیم: بدون `/` انتهایی)
- عمق URL حداکثر ۴ سطح (`/{locale}/products/{category}/{slug}`)

## ۲. ساختار پیشوند زبان (Locale Prefix) — تصمیم نهایی فاز ۰

**استراتژی:** پیشوند فقط برای زبان‌های غیرپیش‌فرض. فارسی (بازار اصلی/داخلی) روی ریشه‌ی دامنه بدون پیشوند قرار می‌گیرد؛ انگلیسی و عربی با پیشوند صریح — و این دو فقط وقتی در پروژه «فعال» شده‌اند نمایش داده می‌شوند (یعنی اگر en/ar هنوز آماده نیستند، سوییچر زبان و مسیرهای آن‌ها اصلاً build نمی‌شوند، نه اینکه خالی/ناقص باشند).

```
/...        → فارسی (پیش‌فرض، RTL) — بدون پیشوند، مثلاً /products
/en/...     → انگلیسی (LTR) — فقط بعد از فعال‌سازی
/ar/...     → عربی (RTL) — فقط بعد از فعال‌سازی
```

**قواعد پیاده‌سازی (next-intl، حالت `localePrefix: "as-needed"`):**
- مسیر ریشه (`/`, `/products`, `/products/{slug}`, ...) همیشه فارسی را نشان می‌دهد — **هیچ ۳۰۱ Redirect خودکاری بر اساس Accept-Language/کشور کاربر روی صفحه‌ی اصلی انجام نمی‌شود.** برند در بازار داخلی (ایران) پیش‌فرض است؛ کاربران انگلیسی/عربی‌زبان از طریق سوییچر زبان در Header به نسخه‌ی خودشان می‌روند.
- سوییچر زبان همیشه در Header نمایش داده می‌شود؛ اگر en یا ar غیرفعال باشند، گزینه‌ی آن‌ها اصلاً در سوییچر نیست (نه Disabled — حذف کامل).
- در `SiteSettings` یک فیلد `enabledLocales[]` تعریف می‌شود تا فعال/غیرفعال‌بودن هر زبان از پنل ادمین قابل کنترل باشد بدون نیاز به Deploy مجدد کد (محتوای همان زبان می‌تواند از قبل در CMS آماده شود، فقط نمایش عمومی آن با این فلگ کنترل می‌شود).

## ۳. نقشه‌ی کامل مسیرها (Route Map)

| مسیر | توضیح |
|---|---|
| `/{locale}` | صفحه‌ی اصلی |
| `/{locale}/products` | لیست همه‌ی محصولات (فیلتر با query param: `?category=chairs&sort=price-asc`) |
| `/{locale}/products/{category-slug}` | لیست محصولات یک دسته |
| `/{locale}/products/{category-slug}/{product-slug}` | جزئیات محصول |
| `/{locale}/portfolio` | لیست نمونه‌کارها |
| `/{locale}/portfolio/{project-slug}` | جزئیات یک پروژه |
| `/{locale}/blog` | لیست وبلاگ |
| `/{locale}/blog/{post-slug}` | جزئیات پست |
| `/{locale}/about` | درباره‌ی ما |
| `/{locale}/contact` | تماس با ما |
| `/{locale}/quote-request` | فرم درخواست استعلام قیمت (B2B) |
| `/{locale}/loyalty-club` | معرفی باشگاه مشتریان (عمومی) |
| `/{locale}/cart` | سبد خرید |
| `/{locale}/checkout` | فرآیند پرداخت |
| `/{locale}/order-confirmation/{orderNumber}` | تأیید سفارش |
| `/{locale}/auth/login` \| `/register` \| `/forgot-password` | احراز هویت |
| `/{locale}/account` | داشبورد مشتری |
| `/{locale}/account/orders` | تاریخچه‌ی سفارش |
| `/{locale}/account/loyalty` | امتیاز و جوایز |
| `/{locale}/account/addresses` | آدرس‌ها |
| `/{locale}/search?q=...` | نتایج جستجو |
| `/admin` | پنل مدیریت Payload (بدون locale، داخلی) |

> در جدول بالا `{locale}` برای فارسی **خالی** است (مثلاً `/products/{slug}`)؛ برای انگلیسی/عربی برابر `en` یا `ar` است (مثلاً `/en/products/{slug}`).

**قوانین فیلتر محصولات:** فیلترها همیشه Query Param هستند نه بخشی از Path (برای جلوگیری از انفجار ترکیبی URLهای قابل ایندکس). فقط دسته‌بندی اصلی در Path می‌آید.

## ۴. چک‌لیست سئو (اجباری در هر صفحه)

### متادیتا
- [ ] `<title>` یکتا و توصیفی، حداکثر ۶۰ کاراکتر
- [ ] `meta description` یکتا، ۱۵۰–۱۶۰ کاراکتر
- [ ] `canonical` تعریف‌شده روی هر صفحه (حتی صفحات با فیلتر → canonical به نسخه‌ی بدون فیلتر)
- [ ] `hreflang` متقابل بین همه‌ی نسخه‌های زبانی هر صفحه (`fa-IR`, `en`, `ar`) + `x-default` که همیشه به نسخه‌ی فارسی بدون پیشوند (ریشه) اشاره می‌کند
- [ ] Open Graph کامل: `og:title`, `og:description`, `og:image` (اختصاصی، نه لوگوی عمومی برای هر صفحه)

### Structured Data (JSON-LD)
- [ ] `Organization` در صفحه‌ی اصلی
- [ ] `Product` + `Offer` + `AggregateRating` (در صورت وجود نظر) در صفحه‌ی محصول
- [ ] `BreadcrumbList` در تمام صفحات عمیق‌تر از سطح ۱
- [ ] `Article` در پست‌های وبلاگ
- [ ] `LocalBusiness` برای هر شعبه/کشور (از `SiteSettings.officesByCountry`)

### فایل‌های فنی
- [ ] `sitemap.xml` پویا (تولید خودکار از Payload، شامل همه‌ی Localeها با `hreflang` annotation)
- [ ] `robots.txt` (بلاک مسیرهای `/admin`, `/account`, `/checkout`, `/cart`, `/api`)
- [ ] `/manifest.json` برای PWA پایه (اختیاری، فاز بعد)

### عملکرد (Core Web Vitals) — بحرانی به‌خاطر UI سه‌بعدی
- [ ] LCP < 2.5s → صحنه‌ی سه‌بعدی Hero نباید LCP را بلاک کند (تصویر placeholder با blur تا لود کامل مدل)
- [ ] کانواس سه‌بعدی و کتابخانه‌ی Three.js فقط زمانی لود شود که در Viewport نزدیک شود (`dynamic import` + `IntersectionObserver`)
- [ ] فایل‌های مدل سه‌بعدی فشرده (Draco/Meshopt)، حداکثر حجم مشخص‌شده در فاز ۲
- [ ] CLS < 0.1 → ابعاد ثابت برای تمام container های تصویر/کانواس قبل از لود
- [ ] روی موبایل/دستگاه کم‌توان: Fallback به تصویر/ویدئوی از پیش رندرشده به‌جای صحنه‌ی سه‌بعدی زنده

### محتوا
- [ ] هر تصویر دارای `alt` معنادار و 🌐 (ترجمه‌شده)
- [ ] ساختار Heading منطقی (یک `h1` در هر صفحه، سلسله‌مراتب درست `h2`→`h3`)
- [ ] لینک داخلی بین محصولات مرتبط، دسته‌ها، و پست‌های وبلاگ مرتبط

## ۵. استراتژی چندزبانه برای سئو
- محتوای هر زبان باید **ترجمه‌ی واقعی و بومی‌سازی‌شده** باشد، نه ترجمه‌ی ماشینی مستقیم بدون بازبینی — گوگل محتوای نازک/تکراری بین زبان‌ها را جریمه می‌کند
- Slug هرزبان مستقل تعریف شود (مثلاً `/products/صندلی-اداری` برای فارسی در ریشه، و `/en/products/office-chairs` برای انگلیسی — تصمیم نهایی درباره‌ی لاتین یا فارسی‌بودن Slug فارسی در فاز طراحی URL نهایی می‌شود)
- `Search Console` باید برای هر Locale (یا هر Property) جدا تنظیم و Sitemap جدا ارسال شود
