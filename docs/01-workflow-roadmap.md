# ۰۱ | Workflow کامل ساخت پروژه (فازبندی)

این سند نقشه‌ی راه گام‌به‌گام است. هر فاز باید **قبل از رفتن به فاز بعد** تکمیل و تأیید شود. در پایان هر فاز، AI باید یک گزارش در `/docs/progress/phase-XX-<name>.md` بنویسد که شامل: چه چیزی ساخته شد، چه تصمیماتی گرفته شد، چه چیزی باقی مانده.

قانون کلی برای AI: **در هر فاز فقط همان فاز را بساز، وارد فاز بعدی نشو مگر تأیید بگیری.**

> **تصمیم مهم (بازبینی بعد از فاز ۰):** ترتیب فازها **UI-first** است — عمداً. به‌جای قفل‌کردن مدل داده قبل از دیدن UI واقعی، اول کل تجربه‌ی کاربری صفحه‌به‌صفحه با داده‌ی Mock ساخته می‌شود (فاز ۳)، بعد مدل داده با وسواس و بر اساس نیاز واقعی فیلدها نهایی می‌شود (فاز ۴)، بعد داده‌ی واقعی وصل می‌شود (فاز ۵). دلیل: حدس‌زدن Schema قبل از دیدن UI معمولاً به فیلدهای اضافی/ناقص و دوباره‌کاری منجر می‌شود. `02-data-model.md` فعلی یک **Draft v1** است، نه Schema نهایی — فقط برای شکل‌دهی به Mock Data در فاز ۳ استفاده می‌شود.

## فاز ۰ — Discovery و معماری محتوا
**هدف:** قبل از نوشتن حتی یک خط کد، مدل داده و نقشه‌ی سایت مشخص شود.

- [x] **زبان‌ها و جهت متن:** فارسی (ایران، RTL، پیش‌فرض/بدون پیشوند URL) + انگلیسی (LTR، پیشوند `/en`) + عربی (RTL، پیشوند `/ar`). زبان دو و سه (en/ar) فقط وقتی «فعال» شوند build/نمایش داده می‌شوند (جزئیات در `03-url-structure-seo.md`).
- [x] **دسته‌بندی اولیه‌ی محصولات (داینامیک، قابل‌تغییر از پنل):** صندلی، میز، مبلمان اداری، آمفی‌تئاتر، همایش و سینما — جزئیات و منطق `salesMode` هر دسته در `02-data-model.md`.
- [x] **پرسونا:** اولویت اول مشتری سازمانی/B2B (تدارکات، پروژه‌های سالن/آمفی‌تئاتر)، اولویت دوم مشتری خرد/B2C. طراحی UX و مسیر خرید باید هر دو را پوشش دهد ولی جریان B2B (استعلام، حساب سازمانی) در اولویت تجربه است.
- [x] **جغرافیای فروش:** فعلاً فقط داخل ایران (بدون صادرات فعلی). زبان عربی سایت به جغرافیای فروش ربطی ندارد و صرفاً پوشش محتوایی است.
- [x] **مدل نمایش قیمت:** ترکیبی — محصولات `direct-purchase` (خرد/تکی) قیمت عمومی دارند، محصولات `quote-only` (پروژه‌ای/تیراژبالا) فقط دکمه‌ی استعلام دارند، بدون نیاز به ورود برای دیدن قیمت (جزئیات در `02-data-model.md`).
- [ ] دسته‌های پروژه‌محور (آمفی‌تئاتر/همایش و سینما): تصمیم `salesMode` پیش‌فرض هر دسته **آگاهانه به بعد موکول شد** — Schema از قبل آماده است، فقط باید بعداً مقداردهی شود.
- [x] **حساب کاربری B2B:** برای MVP تک‌کاربره در سطح شرکت؛ پنل چندکاربره با نقش به Backlog نسخه‌ی بعد منتقل شد (جزئیات مدل در `02-data-model.md`).
- [ ] انتخاب نهایی درگاه پرداخت ایرانی (زرین‌پال/آیدی‌پی/زیبال/نکست‌پی) — **عمداً به بعد موکول شد؛ `paymentProvider` به‌صورت enum عمومی در مدل آماده است**
- [x] **بررسی در‌دسترس‌بودن سرویس‌های خارجی:** Vercel/Neon/Supabase/Cloudflare R2/Resend/Sentry همگی به‌دلیل تحریم برای کسب‌وکار ایرانی قابل‌اتکا نیستند (شرکت‌های آمریکایی، محدودیت در ToS خودشان، نه فیلترینگ). جایگزین شدند با **Liara** (هاست + دیتابیس + Object Storage + ایمیل) و **GlitchTip Self-hosted** (مانیتورینگ خطا) — جزئیات و منابع در `00-tech-stack.md` بخش ۱.۱.

- [x] Sitemap اولیه (خروجی این فاز → `05-pages-build-order.md`)
- [x] مدل داده‌ی اولیه/Draft v1 (خروجی → `02-data-model.md`؛ نسخه‌ی Final در فاز ۴)
